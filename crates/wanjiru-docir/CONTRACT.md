This file is the contract of the crate. A change to the public API, an invariant, an oracle, the budget or the dependency list changes this file in the same commit, and an ADR when the change is a decision.

## Purpose

DocIR is the single result type of the engine (ADR-004): pages, lines, words and typed fields, each with a confidence and a provenance. Geometry is stored in source pixels together with invertible transform chains. This crate owns the model, its JSON Schema, a strict JSON reader, the canonical serialisation used for hashing and signing, and the transform-chain algebra.

## Public API

Implemented in this phase and described in the crate documentation; the list is the contract.

- `Document`, `Page`, `Line`, `Word`, `Field`, `FieldKind`, `Decision`, `DocClass`, `Evidence`, `SourceInfo`, `Run`, `Confidence`.
- `Chain`, `Step`, `Transform`, `Homography<A, B>`: composable, invertible transform chains between named frames.
- `Json` (value type), `parse`, `parse_bytes`, `to_canonical_string`, `canonical_sha256`, `format_number`: a strict JSON reader and the canonical form of RFC 8785.
- `schema::{validate, check, docir_schema, DOCIR_SCHEMA}` for `schema/docir-v0.schema.json`; `Document::{to_json, from_json, from_json_str, to_canonical_string, canonical_sha256, content_sha256}`; `SCHEMA_ID` (`wanjiru.docir/0`).

## Invariants

1. A `Document` built through the API serialises to JSON that validates against the schema; one that would not is refused with the path of the offending value.
2. Canonical JSON is a function of the value: keys in UTF-16 code-unit order, no insignificant whitespace, numbers as ECMAScript writes them, strings escaped as `JSON.stringify` does.
3. The JSON reader is strict: duplicate keys, NaN, Infinity, numbers that overflow, lone surrogates and nesting deeper than 128 are refused. `Document::from_json` never accepts a value that the schema validator refuses.
4. `from_json(to_json(d)) == d`, and the canonical bytes are the same after the round trip.
5. A later schema version (`wanjiru.docir/1`) is refused with its own code, `WNJ-E1006`; a foreign schema identifier with `WNJ-E1003`.
6. Confidences lie in [0, 1] and are never NaN; a `Confidence` records whether it is calibrated.
7. A transform chain is connected (each step starts in the frame where the previous one ended). Arithmetic is `f64`; a round trip is exact to about 1e-6 px for points up to 10^4 px and chains whose condition number is below 10^3, and the `f32` coordinates stored in a document add about 6e-8 times the coordinate.
8. `content_sha256` ignores `run.timing_ms`: the same input and configuration give the same content hash on every run.

## Oracles

What the crate is checked against, independently of its own tests:

- Number formatting equals `String(x)` of Node.js, the definition of RFC 8785, on at least 10,000 doubles, among them the Appendix B vectors, the boundaries of the exponent notation and the cases where two shortest representations tie.
- The reader and the canonical writer agree with Python's `json` (made as strict as this crate) and with `JSON.stringify` on at least 500 valid and 300 invalid texts.
- The validator agrees with the `jsonschema` package (draft 2020-12) on at least 80 valid and 250 invalid documents, and the typed reader (`Document::from_json`) never accepts one that the validator refuses.
- Transform chains (apply, compose, invert) agree with NumPy 3x3 matrix arithmetic on 225 random chains, homographies included (at least 1,000 points).
- A sample invoice is the same document built in code and read from JSON, and its hashes are computed by `hashlib`.
- Vectors are generated by `tools/oracles/make_docir_vectors.py` and committed under `tests/golden/`.
- `tests/robustness.rs`: 21,500 mangled copies of real documents and 10,000 byte-level corruptions (invalid UTF-8 included) are read, validated and written canonically without a panic. The test was checked to fail when a fault is injected into the reader. Nesting deeper than 128 is refused with an error (unit test).
