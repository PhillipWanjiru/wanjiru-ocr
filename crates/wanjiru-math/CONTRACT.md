This file is the contract of the crate. A change to the public API, an invariant, an oracle, the budget or the dependency list changes this file in the same commit, and an ADR when the change is a decision.

## Purpose

Own implementations of every numeric routine whose result must not depend on the platform: edit distance, descriptive statistics and exact interval methods, compensated and fixed-tree summation, a seeded random generator, SHA-256, and an exponential function built from basic IEEE operations only. This is the foundation of determinism tiers 1 and 2 (ADR-005).

## Public API

Implemented in this phase and described in the crate documentation; the list is the contract.

- `edit_distance::{levenshtein, levenshtein_dp, levenshtein_chars}`: Myers' bit-parallel distance over any ordered symbol type, with the quadratic dynamic programme beside it as its oracle.
- `stats::{mean, variance, std_dev, quantile_sorted}` (Hyndman-Fan type 7), `binomial_cdf`, `binomial_sf`, `clopper_pearson`, `quantile_rank_interval` (distribution-free interval for a quantile, by order statistics).
- `summation::{neumaier_sum, pairwise_sum, dot_fixed_tree}`.
- `rng::{SplitMix64, Rng}`: xoshiro256** seeded by SplitMix64, with `next_u64`, `next_f64` and unbiased bounded integers (`below`).
- `digest::{Sha256, sha256, sha256_hex, to_hex}`.
- `special::{exp, normal_pdf, normal_cdf, normal_quantile}`, without the platform's maths library.

## Invariants

1. Same inputs give bit-identical outputs on every platform, thread count and optimisation level: only operations that IEEE 754 defines exactly (`+ - * /`, `sqrt`, `floor`, `ceil`, `abs`, comparisons) and bit operations are used. No `exp`, `ln`, `powf`, `powi`, `sin` or other platform function appears in non-test code; `cargo xtask check-determinism` enforces it.
2. No global state, no I/O, no hash-seeded containers.
3. Random streams are specified by the algorithm, not by a library version.
4. Summation order is fixed by the function, never by the scheduler.

## Oracles

What the crate is checked against, independently of its own tests:

- `sha256` agrees with `hashlib` on 140 inputs: every length from 0 to 130 bytes, which covers the padding and block boundaries, and nine longer ones.
- `exp` is within 2 ulp of a 50-digit `decimal` reference on at least 1,900 arguments; the test prints the worst error.
- `normal_cdf` agrees with SciPy to a relative 3e-14 (left tail) or an absolute 1e-15 on at least 2,000 arguments, `normal_quantile` to a relative 1e-11 on at least 1,000.
- `binomial_cdf` and `binomial_sf` agree with SciPy to a relative 1e-9, `clopper_pearson` with SciPy's beta quantiles to 1e-9, on 1,500 cases each; `quantile_rank_interval` returns the same integer ranks as the reference on 180 cases.
- `levenshtein` equals `levenshtein_dp` on 100,000 random pairs (unit test, lengths above 64 and 128 included), and both equal an independent Python dynamic programme on at least 450 pairs.
- `Rng` produces the same `u64`, `f64` and bounded streams as an independent Python port, for several seeds.
- `neumaier_sum` is within 4 machine epsilons, relative to the exact sum (`math.fsum`), plus a second-order term, on 150 adversarial inputs.
- All vectors are generated by `tools/oracles/make_math_vectors.py` and committed under `tests/golden/`, so the Rust tests need no Python.

## Budget

- Entries `B-math-01` to `B-math-04` in `docs/budgets.md`: Myers distance on 5,000 x 5,000 symbols, Clopper-Pearson at n = 10^5, SHA-256 throughput, `exp` throughput. A regression above 5 % blocks a merge once the reference machine is fixed (Phase 10).
